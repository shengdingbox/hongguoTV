# 播放算法自动切换

「自动切换」开关只放在手机和电视设置页。算法弹窗读取外部开关状态：开启时提示「自动模式不能切换」，仍可检测算法；关闭后允许手动选择和确认。弹窗不再展示自动切换策略的说明文字。外部开关切换立即作用于后续取址，正在播放的视频继续使用原媒体源。

内置算法默认启用自动切换；已有自定义服务的配置默认保留手动模式。关闭开关后严格使用保存的手动算法，不自动降级，也不进行本地恢复探测。自动选择与手动算法分别保存，自动降级不会覆盖手动选择；重新开启自动切换或应用冷启动时从本地开始。

## 自动策略

1. 首先使用本地算法。同一次正式取址可以在内部重试；本地连续三次完整取址失败后，尝试 unidbg。每个算法内部的接口、主机和兼容性重试不单独累计策略失败。
2. unidbg 失败后尝试 Frida。远程成功后由应用级策略保留该算法，下一次取址直接沿用，不再先等待本地失败。
3. 本地第三次失败后开始五分钟冷却。冷却到期后，在下一次取址或播放中的定时检查中，独立发起一次本地真实取址探测。探测使用新缓存和独立的路由健康状态，不能用旧地址或仅成功生成签名来证明恢复。
4. 探测成功立即恢复本地，随后取址重新本地优先；探测一轮最多三次：第一次失败后等待二秒，第二次失败后等待四秒，任意一次成功立即恢复本地；第三次仍失败则继续使用远程，从整轮失败起再冷却五分钟。探测及等待都不阻塞正在执行的远程请求。
5. 远程失败也会短暂冷却，避免服务持续不可用时反复请求。所有候选都冷却时快速返回，由播放页原有重试处理，不弹出要求用户切换算法的强制窗口。

自动正式取址总预算为二十五秒，本地最多三轮、两个远程各一轮，每轮最多五秒。手动正式取址保留八秒预算，后台预取保留两秒预算。本地恢复探测每次最多五秒，三次尝试之间分别等待二秒和四秒。

## 并发与告警

- 每次取址绑定同一个签名器和设备画像；缓存与路由健康度按签名器分区，切换前的在途请求不会污染另一算法。
- 状态更新由短临界区保护，网络操作在锁外执行。算法版本用于忽略旧结果，成功水位用于忽略在最近成功之前发出的延迟失败。
- 本地恢复探测在应用内全局只允许一个并发任务。远程算法之间切换不会丢弃有效的本地恢复结果，用户更改开关或手动选择则会使旧探测结果失效。
- 同一远程服务地址共用一个公平签名队列，排队和签名网络请求合计最多四秒，并服从更短的外层预算。取消的请求不再进入远程服务队列。
- 预取和下载失败不计入前台连续失败，也不触发全局降级或不可用弹窗。后台真实取址成功仍可清除同一有效版本的失败状态；缓存命中不作为算法恢复证据。
- 手动模式只有前台连续三次完整取址失败时才提示当前集暂时取址失败。播放器已有视频就绪时不弹诊断框，不再把失败次数表述为算法完全不可用。

## 后三集缓存

后三集按下 1 集、下 2 集、下 3 集严格串行下载，调度器和下载线程都限制为单路。当前集缓冲不足时暂停后台下载，缓冲充足后从已有落盘区间续传。前一集未完成或处于失败退避时，后面的集保持等待；切集、回看或切画质后按新窗口重新确定最近的未完成分集，并取消低优先级的旧任务。
